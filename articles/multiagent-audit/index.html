Многоагентная система для аудита процессов

Как спроектировать команду специализированных агентов, которые собирают данные, находят узкие места и предлагают решения без человеческого вмешательства.

Когда я впервые столкнулся с задачей аудита бизнес-процессов, меня удивило, насколько много времени уходит не на анализ, а на сборку данных из десятков источников. CRM, ERP, таск-трекеры, почта, чаты — каждая система говорит на своём языке. Идея многоагентной системы родилась из этого хаоса.

Архитектура команды агентов

Вместо одного универсального помощника я разделил систему на четыре роли:

  • Collector Agent — собирает сырые данные из подключённых систем.
  • Analyzer Agent — ищет аномалии, задержки и повторяющиеся проблемы.
  • Advisor Agent — формулирует гипотезы и рекомендации.
  • Validator Agent — проверяет, не противоречат ли рекомендации ограничениям бизнеса.

Почему не один большой LLM?

Один агент с широким контекстом быстро теряет фокус. Он начинает путать приоритеты, забывает ограничения и даёт размытые советы. Специализированные агенты решают конкретные задачи и общаются через чёткий протокол — это делает систему предсказуемой и масштабируемой.

Протокол взаимодействия

Каждый агент получает структурированный вход и возвращает структурированный выход. Я использую JSON-схемы с обязательными полями: observation, confidence, reasoning, recommendation. Это позволяет отслеживать, почему система приняла то или иное решение.

Первые результаты

На пилоте система нашла 14 узких мест в процессе обработки заказов, из которых 6 были неочевидны для команды. Время аудита сократилось с трёх дней до четырёх часов. Главное — не скорость, а повторяемость: теперь аудит можно запускать раз в неделю без дополнительных ресурсов.
